🧩 HyperToken

A game engine where the entire state is a conflict-free replicated data type (CRDT).

Deterministic replay. Serverless multiplayer. Forkable worlds. Built on Automerge for distributed consensus, with optional Rust→WASM acceleration for hot paths. Games, collaborative tools, marketplaces — any multi-user app where state must converge.

How It Works

Tokens Compose With Provenance

const enchantedSword = engine.dispatch("token:merge", {
  tokens: [sword, fireEnchantment],
  properties: { label: "Flaming Sword" }
});
// enchantedSword._mergedFrom = [sword.id, fireEnchantment.id]

const pieces = engine.dispatch("token:split", {
  token: goldPile,
  count: 3
});
// pieces[0]._splitFrom = goldPile.id

State Syncs Automatically

const host = new Engine();
host.connect("ws://relay.local:8080");

const client = new Engine();
client.connect("ws://relay.local:8080");

// Both make changes → CRDTs merge → identical final state
// No conflict resolution code. It just works.

Persistence

const engine = new Engine();

// Use storage adapter (IndexedDB in browser,
// FilesystemAdapter in Node.js)
engine.useStorage(new IndexedDBAdapter());

// Save state
await engine.persist("my-game-session");

// Resume later — even after closing the browser
await engine.resume("my-game-session");

Forkable Worlds

// Fork the engine — divergent branch with new actor ID
const fork = engine.fork();

// Explore timeline A
fork.dispatch('token:merge', { tokens: [sword, fireEnchantment] });
const outcomeA = fork.getState();

// Merge changes back — CRDT conflict resolution
engine.mergeFrom(fork);
const outcomeB = engine.getState();

What's Inside

  • 81 built-in actions — draw, shuffle, place, move, flip, merge, split, and more across 7 categories
  • Rust/WASM core — ~20x performance over pure JS, with TypeScript fallback
  • P2P networking — serverless CRDT sync (ConsensusCore) and host-authoritative mode
  • Persistence — IndexedDB (browser) and Filesystem (Node.js) adapters with auto-save
  • Browser builds — one command bundles any app for the browser
  • MCP server — LLM integration via Model Context Protocol
  • 3 example games — Blackjack (fully CRDT-backed card game), Cuttle (snapshot CRDT sync with encrypted hands), Watershed (field-level CRDT real-time showcase)
  • Document compaction — discard CRDT history at phase boundaries to bound document size
  • Forkable worlds — fork engine state, explore divergent timelines, merge back via CRDT conflict resolution
  • Token provenance — every entity tracks its full merge/split history, useful for games, marketplaces, and collaborative tools
